# Восстановление YubiKey {#yubikey-recovery}

Утилита переносит резервные копии ключей GnuPG, сделанные по этому руководству до `keytocard`, на новые YubiKey. Используйте её, если имеющиеся YubiKey повреждены, утеряны или подлежат замене.

Есть два равноценных инструмента:

- `yubikey-recovery`: графический мастер (`python3 -m ykrecover` из этой папки). Добавьте `--cli`, чтобы пройти те же шаги в терминале.
- `recoverCard.sh`: те же параметры, шаги и коды выхода на bash.

На LiveCD, собранном из `nix/`, установлены оба, а на рабочем столе есть ярлык "YubiKey Recovery".

Инструмент на Python работает в Linux и Windows; скрипт на bash — только в Linux. В других системах оба завершаются с ошибкой.

**Windows:** готовая сборка для загрузки и самостоятельная сборка описаны ниже, в разделе [Windows](#windows).

Запускайте инструмент на Python как пакет из папки `recovery`: `python3 -m ykrecover`. Прямой запуск `ykrecover/gui.py` завершается ошибкой "attempted relative import".

> [!WARNING]
> Каждая записываемая карта **сбрасывается**: все ключи OpenPGP и PIN на ней стираются. Для каждой карты утилита просит ввести `RESET <serial>`.

> [!IMPORTANT]
> Запускайте утилиту в системе, изолированной от сети. Ваша резервная копия копируется во временные домашние каталоги GnuPG в `$XDG_RUNTIME_DIR` (или в `/tmp`, если эта переменная не задана или путь слишком длинный); они удаляются при завершении утилиты. Они находятся в оперативной памяти, только если эта папка расположена на tmpfs, как на LiveCD; иначе утилита выводит предупреждение, и ключевой материал может попасть на диск. В Windows по умолчанию используется `%LOCALAPPDATA%\Temp\ykrecover`, а это папка на диске: файлы перезаписываются перед удалением, но чтобы ключевой материал не попал на диск, укажите RAM-диск или зашифрованный том с помощью `--workdir`.

## Windows {#windows}

### Готовый zip-архив {#use-the-prebuilt-zip}

1. Установите GnuPG: [Gpg4win](https://gpg4win.org) или запустите `Prepare-Windows.bat`, как описано ниже.
2. Скачайте `ykrecover-windows-x64.zip` со страницы [Releases](https://github.com/mezinster/YubiKey-Guide/releases) репозитория (или из артефактов последнего запуска CI `windows`).
3. Распакуйте zip-архив **целиком**. В нём одна папка, `ykrecover-windows-x64`, с `ykrecover.exe`, `ykrecover-gui.exe` и папкой `_internal`, которая нужна обоим; держите их вместе и не запускайте их прямо из zip-архива.
4. В этой папке дважды щёлкните `ykrecover-gui.exe`, чтобы открыть мастер, или выполните `ykrecover.exe --cli --help` в cmd, PowerShell или Windows Terminal (Git Bash отображает вводимую парольную фразу).

Исполняемые файлы не подписаны, поэтому SmartScreen может выдать предупреждение (нажмите "More info" (Подробнее), затем "Run anyway" (Выполнить в любом случае)).

### Самостоятельная сборка {#build-it-yourself}

Вам понадобится копия репозитория на компьютере с Windows.

1. **Подготовьте компьютер**: в Проводнике откройте `recovery\packaging` и дважды щёлкните `Prepare-Windows.bat` (запускайте его обычным образом, *не* через "Запуск от имени администратора"). Скрипт:
   - один раз запрашивает права администратора, только для шага установки;
   - устанавливает Chocolatey, если он отсутствует (закреплённую версию, проверенную по SHA-256);
   - устанавливает Python 3.13 (в `C:\Program Files\Python313`) и GnuPG через Chocolatey, если они ещё не установлены в Program Files (уже установленный Gpg4win используется как есть);
   - добавляет их в системную переменную PATH и задаёт `YKRECOVER_PYTHON`;
   - записывает журнал в `recovery\packaging\logs\`.

   Ваш текущий `python` по умолчанию (например, 3.14) не затрагивается.
2. **Сборка**: в обычном окне cmd (не от имени администратора) в папке `recovery\packaging` выполните:

   ```bat
   powershell -NoProfile -ExecutionPolicy Bypass -File build-windows.ps1
   ```

   Или выполните оба шага сразу: `Prepare-Windows.bat -Build`. Сборка создаёт новое виртуальное окружение, устанавливает закреплённые версии инструментов сборки и записывает `recovery\packaging\dist\ykrecover-windows-x64.zip`.
3. **Проверка сборки** (необязательно): `python smoke_test.py dist\ykrecover-windows-x64\ykrecover.exe` сравнивает пробный запуск с эталонным планом и проверяет встроенный ykman.
4. Используйте zip-архив, как описано в разделе [Готовый zip-архив](#use-the-prebuilt-zip), шаги 3–4.

Примечания:

- Для сборки нужен Python 3.13 или 3.12.4+: у библиотеки для смарт-карт, которую использует ykman, ещё нет пакетов для Windows под Python 3.14. Без `Prepare-Windows.bat` установите Python 3.13 с [python.org](https://www.python.org/downloads/windows/) с параметром "py launcher"; скрипт сборки находит его через `py -3.13` или через `YKRECOVER_PYTHON`, если вы указали в ней путь к `python.exe`.
- `Prepare-Windows.bat -WhatIf` показывает, что будет установлено или изменено, ничего не меняя.
- Просто `build-windows.ps1` из cmd не работает: cmd не может напрямую запускать скрипты PowerShell, поэтому используйте приведённую выше команду `powershell -File`.

### Замечания по безопасности для Windows {#security-notes-for-windows}

- В Windows нет временной папки в оперативной памяти, поэтому, пока утилита работает, копии ключей попадают на диск, и утилита предупреждает об этом. Чтобы этого избежать, выберите в качестве рабочей папки RAM-диск или зашифрованный том (`--workdir DIR` или "Work folder" (рабочая папка) в мастере).
- Если работа завершилась аварийно (закрыто окно консоли, процесс завершён в Диспетчере задач, сбой), её временные папки (`ykr-*` в рабочей папке) могут остаться на диске неперезаписанными. При следующем запуске утилита предупреждает о тех из них, что старше 10 минут; удалите их безопасным способом.
- Собранная утилита всегда запускает встроенный ykman, а GnuPG берёт из папки Gpg4win в Program Files (`GnuPG\bin`) раньше, чем `gpg.exe` из PATH. Запускаются только файлы `.exe`: `ykman.cmd` или `gpg.bat` в PATH игнорируются, поэтому подброшенный скрипт не может получить PIN.
- Пройдите [проверку на оборудовании](#hardware-checklist) и в Windows: доступ к картам там устроен иначе.

## Режимы {#modes}

| Режим | Что записывается на карты | Нужен ключ сертификации | Новая резервная копия |
| - | - | - | - |
| `clone` | подключи из резервной копии без изменений | нет | нет |
| `renew` | те же подключи с новым сроком действия | да | да |
| `rotate` | заново сгенерированные подключи | да | да |

Подробности:

- `renew` и `rotate` сначала продлевают основной ключ до `--expire`, если он истекает раньше нового срока действия подключей, в том числе если срок действия основного ключа уже истёк. Основной ключ без срока действия не изменяется.
- `renew` и `rotate` создают отсутствующий подключ подписи, шифрования или аутентификации. Алгоритм по умолчанию соответствует имеющимся подключам (`rsa4096` для RSA, иначе `ed25519`). `rotate` использует тот же алгоритм по умолчанию, если не указан `--algo`; `renew` не принимает `--algo`.
- `clone` оставляет пустой слот пустым и предупреждает об этом. Если подключа аутентификации нет, файл `ssh-*.pub` не записывается.

Выберите `rotate`, если старые карты могли быть утеряны или оказаться в чужих руках. Добавьте `--revoke-old`, чтобы отозвать прежние подключи.

`renew` и `rotate` записывают новую резервную копию в `--out` и ждут, пока вы подтвердите, что сохранили её, и только потом обращаются к картам. Храните новую резервную копию так же, как исходную.

## Использование {#usage}

```bash
recoverCard.sh --backup /mnt/backup --out /mnt/new-backup --cards 2
recoverCard.sh --backup /mnt/backup --out /mnt/new-backup --mode renew --expire 2y --cards 2
recoverCard.sh --backup /mnt/backup --mode rotate --revoke-old --dry-run
```

`--dry-run` выводит все команды, которые выполнил бы запуск, с заполнителями вида `<ADMIN_PIN>` вместо секретов, и ничего не изменяет.

`--out` обязателен для любого запуска, кроме `--dry-run`, в том числе для `clone`: туда записываются открытый ключ (`public-KEYID-DATE.asc`) и открытый ключ SSH (`ssh-KEYID.pub`), а для `renew` и `rotate` — ещё и новая резервная копия. Эта папка должна находиться вне папки резервной копии и не должна уже содержать файлы `secret-*.key`.

Резервная копия, сделанная по основному руководству, часто содержит и экспортированные файлы ключей (`secret-*-Certify.key`, `secret-*-Subkeys.key`), и копию домашнего каталога GnuPG. В этом случае утилита останавливается и просит выбрать источник с помощью `--source`. Укажите `--source export`: экспорт сделан до `keytocard` и содержит секретные подключи, а домашний каталог GnuPG, скопированный после `keytocard`, содержит только заглушки ключей карты, которые утилита отвергает для `clone` и `renew`.

## Что считается резервной копией {#what-counts-as-a-backup}

`--backup` принимает папку. Утилита просматривает её и до 3 уровней вложенных папок и определяет тип каждого файла по его **содержимому**, а не по имени. Принимаются:

- файлы из руководства, `secret-*-Certify.key` и `secret-*-Subkeys.key`;
- файлы ключей OpenPGP в текстовом (armored) или двоичном формате с любым именем и расширением;
- один ключ, разделённый на несколько файлов (например, основной ключ в одном файле, а подключи в другом);
- несколько ключей в одном файле: выберите нужный с помощью `--key KEYID`;
- незащищённые экспорты, сделанные без парольной фразы: парольная фраза для них не запрашивается;
- домашние каталоги GnuPG 2.x;
- домашние каталоги GnuPG 1.x (`secring.gpg`).

Домашний каталог GnuPG 2.1+, перенесённый с 1.x и всё ещё содержащий `secring.gpg`, даёт два варианта: сам домашний каталог и старый `secring.gpg` как экспорт того же ключа. Выберите один с помощью `--source gnupghome` или `--source export`.

О заглушках ключей карты и открытых ключах сообщается, но они никогда не используются: заглушка не содержит секретного ключа. Файлы сертификатов отзыва (`.rev`) игнорируются. Ключ, который есть только в виде заглушек или открытого ключа, отмечается как "not recoverable from this folder" (невозможно восстановить из этой папки).

Прежде всего утилита выводит в stderr отчёт обо всех найденных файлах (планы выводятся в stdout). Ниже — реальный вывод для тестового набора `flexible`; идентификатор ключа принадлежит тестовому ключу:

```console
$ python3 -m ykrecover --cli --backup "tests/fixtures/flexible/asc backup" --mode renew --dry-run
Backup files in tests/fixtures/flexible/asc backup:
  private/flex.priv.asc: key 5B21983A476B3572: main secret, 2 subkeys secret (used)
  pub/flex.pub.asc: key 5B21983A476B3572: main public, 2 subkeys public (ignored)
  stub/flex.priv_stub.asc: key 5B21983A476B3572: main card stub, 2 subkeys card stub (ignored)
  stub/flex.sub_priv_stub.asc: key 5B21983A476B3572: main missing, 2 subkeys card stub (ignored)
  subkeys/flex.sub_priv.asc: key 5B21983A476B3572: main missing, 2 subkeys secret (not needed)
```

Файлы с пометкой "used" (используется) дают ключ. Файлы с пометкой "not needed" (не нужен) содержат секреты, которые уже есть в другом файле. Если один и тот же ключ есть в нескольких файлах, утилита предпочитает копию, защищённую парольной фразой. Внутри одного файла учитывается первая копия, как и при `gpg --import`. Если в одной папке несколько резервных копий или несколько ключей, утилита перечисляет их и просит сузить `--backup` или указать `--source` или `--key`.

В резервной копии защита может быть смешанной: основной ключ защищён парольной фразой, а подключи — нет. Утилита всё равно запрашивает парольную фразу и передаёт её `keytocard` только для тех подключей, у которых она есть.

`--workdir DIR`: куда помещаются временные домашние каталоги GnuPG (папка должна существовать; в Linux — не длиннее 60 символов)

Все параметры выводит `recoverCard.sh --help`. Значения по умолчанию:

- **PIN:** генерируются, 8-значный PIN администратора и 6-значный PIN пользователя; укажите `--pins enter`, чтобы ввести свои.
- **Число попыток:** `5,5,5`.
- **Касание:** `on` для каждого ключа.
- **Данные владельца карты:** случайный логин и без имени, потому что метаданные карты может прочитать любой, у кого есть карта.

Коды выхода:

| Код | Значение |
| - | - |
| 0 | все карты записаны и проверены |
| 1 | ошибка использования или предварительной проверки |
| 2 | проблема с резервной копией или парольной фразой |
| 3 | сбой карты или карта пропущена |
| 130 | прервано |

## После записи карт {#after-writing-the-cards}

На своём повседневном компьютере укажите GnuPG новые карты и переместите в сторону заглушки ключей повреждённых карт:

```bash
recoverCard.sh update-stubs --import /mnt/new-backup/public-KEYID-DATE.asc --remove-serial OLD_SERIAL --cards 2
```

`--remove-serial` принимает десятичный серийный номер YubiKey (только цифры, как напечатано на карте или выводится `ykman list`) и сравнивает его с полем серийного номера в идентификаторе карты каждой заглушки. Совпавшие заглушки перемещаются в новую папку `stub-backup-*` в домашнем каталоге GnuPG и никогда не удаляются. Если `learn` для какой-либо карты завершается ошибкой, команда завершается с кодом 3.

Если вы продлили или заменили подключи, опубликуйте также новый открытый ключ везде, где публиковали старый.

## Как это работает {#how-it-works}

1. Резервная копия импортируется во временный промежуточный (staging) домашний каталог GnuPG. Сама резервная копия только читается.
2. Режим применяется в промежуточном каталоге.
3. Для каждой карты промежуточный каталог копируется в новый домашний каталог. Карта сбрасывается; счётчики попыток ввода PIN задаются, пока PIN ещё стандартные (изменение счётчиков попыток может сбросить PIN); PIN меняются; задаются данные владельца карты; `keytocard` переносит подключи; задаётся политика касания; после этого копия удаляется. Промежуточный каталог никогда не расходуется, поэтому запись на карту после сбоя можно безопасно повторить. Перед повтором утилита проверяет, что подключена всё та же карта и только она, и в противном случае просит переподключить её.
4. Третий домашний каталог, содержащий только открытый ключ, проверяет карту:
   - отпечатки на карте совпадают с подключами;
   - тестовая подпись проходит проверку;
   - тестовое сообщение расшифровывается.

   Если касание включено (по умолчанию), перед тестовой подписью и перед расшифровкой утилита выводит "Touch the YubiKey when it blinks" (коснитесь YubiKey, когда он замигает): каждый раз касайтесь карты, иначе время ожидания шага истечёт и запись карты завершится сбоем.

PIN каждой карты, у которой они были изменены, показываются один раз, в конце, в том числе для карт, запись которых завершилась сбоем или была прервана, и для запусков, остановленных по Ctrl-C, SIGTERM, SIGHUP или (в Windows) Ctrl-Break, — чтобы частично записанная карта никогда не осталась с неизвестными PIN. Графический интерфейс показывает их сразу после окончания записи карт. Тогда же и запишите их.

Оба инструмента работают с umask 077, поэтому всё, что записывается в `--out`, доступно для чтения только владельцу.

Перед каждым сеансом работы с картой (каждым автоматизированным запуском `gpg --change-pin`, `--edit-card` или `--edit-key`) и каждой командой ykman выполняется `gpgconf --kill all`: он сбрасывает кешированные парольные фразы и сеансы карты, чтобы запросы всегда приходили в ожидаемом порядке.

PIN администратора передаётся `ykman` через `-a`, как в основном руководстве. На многопользовательском компьютере другие пользователи могут ненадолго увидеть его в списке процессов; в предполагаемой однопользовательской системе, изолированной от сети, этого риска нет. В Windows, которая обычно используется как повседневная и, возможно, управляемая организацией система, аудит создания процессов или средства защиты конечных точек могут записывать командные строки, включая PIN администратора: на управляемом или контролируемом аудитом компьютере смените PIN администратора после работы (`ykman openpgp access change-admin-pin`).

## Разработка {#development}

Запускайте тесты из этой папки:

```bash
python3 -m unittest discover -s tests -t . -v
```

- Реализации на Python и на bash должны выводить идентичные планы `--dry-run`. Эталонные планы хранятся в `tests/golden/`.
- После намеренного изменения обновите код на Python, пересоздайте эталоны командой `UPDATE_GOLDEN=1 python3 -m unittest tests.test_plan_parity`, просмотрите изменения, затем приведите bash в соответствие.
- Операции с картами тестируются на имитациях из `tests/fakebin/`.

## Проверка на оборудовании {#hardware-checklist}

Выполните эту проверку на запасном YubiKey, прежде чем работать с настоящими резервными копиями, и повторите её после обновления GnuPG, ykman или прошивки YubiKey. Используйте тестовые ключи из `tests/fixtures/` (парольная фраза `test-certify-pass`).

- [ ] `clone` из `tests/fixtures/ed25519/export` на одну карту через графический интерфейс: во время проверки дважды появляется "Touch the YubiKey when it blinks", карта каждый раз мигает, а после касания карта получает статус OK. `gpg --card-status` показывает три отпечатка тестового набора, а `Login data` начинается с `yk.`.
- [ ] `clone` из `tests/fixtures/rsa4096/export` с `recoverCard.sh --touch off`: OK, и атрибуты ключей показывают `rsa4096` для всех трёх слотов.
