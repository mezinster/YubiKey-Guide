# Создание защищённой среды для GPG в Alpine Linux {#creating-a-secure-environment-for-gpg-in-alpine-linux}

Copyright (c) 2025 Matt Borja

## Аннотация {#abstract}

В этом документе описан процесс создания защищённой среды для управления ключами GPG на базе Alpine Linux — лёгкого и безопасного дистрибутива Linux, который поддерживает новые версии GPG с поддержкой смарт-карт даже на очень скромном оборудовании, например на Raspberry Pi 1 Model B (32-разрядный, на базе ARM). Также рассматривается высокая переносимость Alpine Package Keeper (APK), упрощающая установку зависимостей в изолированных от сети средах, и тесно связанная с установкой процедура, которая дополнительно подтверждает целостность пакетов как обязательное условие их установки в изолированной от сети среде.

**Теги.** Tails OS, Alpine Linux, GnuPG, Raspberry Pi.

## Отказ от ответственности {#disclaimer}

Описанные в этом документе процедуры предлагаются как меры, принимаемые по мере возможности (best effort), для создания более безопасной рабочей среды для управления ключами GPG. Они не предназначены для устранения всех возможных угроз, включая, но не ограничиваясь угрозами, связанными с наличием: целевых продолжительных атак (APT), вирусов, заражённой прошивки или других подобным образом скомпрометированных периферийных устройств или протоколов, используемых в этих процедурах. ## 1. Подготовка защищённого хоста для записи образа {#1-prepare-a-secure-imaging-host}

Обычно для подготовки защищённой среды для GPG сначала используется внешняя хост-система (например, Windows, Mac OS и т. п.), на которой создаётся загрузочный диск. Многих это может устроить, но стоит учитывать риск того, что хост заражён в ходе повседневного использования. Поэтому мы рассмотрим *промежуточную среду*, из которой затем создадим загрузочный диск. Этот, казалось бы, лишний шаг можно сравнить с тем, чтобы взять чистую тарелку, прежде чем положить на неё еду!

### 1.1. Использование Tails OS в качестве промежуточной среды (рекомендуется) {#11-use-tails-os-as-an-intermediary-recommended}

[Tails OS](https://tails.net/install/expert/index.en.html) — удобная изолированная временная среда, в которой особое внимание уделяется надлежащей проверке её USB-образов перед использованием. Рекомендуется загрузиться в подобную систему, прежде чем приступать к этим процедурам.

Как уже говорилось, одной этой среды, пожалуй, можно считать достаточно для работы с GPG, но из соображений повышенной осторожности мы используем её только для проверки и записи образов.

### 1.2. Загрузка пакетов и gpg.conf с помощью целевой ОС {#12-use-the-target-os-to-download-packages-and-gpgconf}

Цель этого раздела — заранее получить все необходимые материалы, чтобы после установки, ближе к концу руководства, подключение к Интернету не понадобилось.

#### 1.2.1. Получение целевого образа {#121-acquire-the-target-image}

Если вы ещё этого не сделали, *внимательно* выполните [инструкцию по установке Tails](https://tails.net/install/expert/index.en.html), чтобы перед продолжением убедиться, что вы [проверили](https://tails.net/install/expert/index.en.html#verify-key) подлинную среду Tails и загрузились в неё.

Затем перенесите копию [Alpine Linux](https://alpinelinux.org/downloads/) одним из способов:

- подключите Tails к Интернету и скачайте образ в Tor Browser;
- оставьте Tails отключённой от Интернета, а скачанный образ перенесите с другого устройства (например, смартфона) на съёмном носителе.

**Примечание.** Если в качестве изолированного от сети устройства вы выбрали старый Raspberry Pi, вам понадобится SD-карта для записи образа и, скорее всего, образы ARMhf (hard float) со [страницы загрузок](https://www.alpinelinux.org/downloads/).

**Важно.** Так же, как вы должны были сделать это для Tails, перед продолжением необходимо проверить образ Alpine Linux по соответствующей подписи GPG с помощью ключа, которым он подписан. Всегда сверяйтесь с [официальными источниками](https://docs.alpinelinux.org/user-handbook/0.1a/Installing/medium.html#_optional_verifying_the_downloaded_files_pgp) и для полноты проверки подлинности привлекайте дополнительные источники подтверждения ([пример](https://sig3.dev)). Эти шаги могут показаться утомительными и повторяющимися, но они критически важны для построения проверяемого пути к высокозащищённой среде.

Проверив скачанный образ, вы можете записать его на целевой диск (например, на SD-карту для Raspberry Pi) с помощью пункта **Restore Disk Image...** (Восстановить образ диска) в утилите *Disks* (Диски) в Tails.

#### 1.2.2. Скачивание копии gpg.conf (с усиленными настройками) {#122-download-a-copy-of-gpgconf-hardened}

Пока подключение к Интернету ещё есть, рекомендуется скачать копию gpg.conf с усиленными настройками безопасности ([пример](https://github.com/drduh/YubiKey-Guide/blob/master/config/gpg.conf)), чтобы добавить её в `$GNUPGHOME` при первой загрузке защищённой среды.

#### 1.2.3. Запуск целевого образа и скачивание пакетов GnuPG для этой ОС {#123-boot-the-target-image-to-download-os-specific-packages-for-gnupg}

Загрузите систему Alpine Linux, войдите как `root` и подключитесь к Интернету, чтобы скачать пакеты, необходимые для этой платформы:

```shell
# 1. Set date
root@host:~$ date -s 'YYYY-MM-DD hh:mm:ss'

# 2. Connect to Internet (https://wiki.alpinelinux.org/wiki/Configure_Networking)

# 3a. Download packages for offline installation
root@host:~$ apk update
root@host:~$ apk upgrade
root@host:~$ apk fetch --recursive gpg gnupg-scdaemon pcsc-lite

# 3b. Use the same apk fetch --recursive command to download any additional packages you require for additional work in the air-gapped enviroment.

# Note. Internet is no longer required beyond this point.

# 4. Review downloaded packages
root@host:~$ ls -lha *.apk

# 5. Bundle for offline use and take SHA256 checksum
root@host:~$ tar -czvf airgap-bundle.tar.gz *.apk
root@host:~$ sha256sum airgap-bundle.tar.gz > airgap-bundle.tar.gz.sha256

# 6. Visually inspect and note SHA256 checksum for verification
root@root:~$ cat airgap-bundle.tar.gz.sha256

# 6. Mount removable storage and transfer (replace $SD_PARTITION_DEV with your actual device file handle, as in /dev/sda1, etc.)
root@host:~$ mount -t exfat "${SD_PARTITION_DEV}" /mnt
root@host:~$ cp airgap-bundle.* /mnt/
root@host:~$ umount /mnt
```

**Примечание.** Теперь, когда пакеты для автономной установки у вас на руках, можно повторить предыдущий раздел (*1.2.1. Получение целевого образа*), чтобы перед продолжением взять ещё одну «чистую тарелку» — ни разу не подключавшуюся к Интернету. С практической точки зрения можно и просто «вымыть тарелку»: заново записать образ Alpine Linux на ту же SD-карту, с помощью которой на этом шаге скачивались пакеты.

## 2. Запуск защищённой среды {#2-boot-the-secure-environment}

Теперь загрузите только что подготовленную среду Alpine Linux, отключив все лишние периферийные устройства и полностью отключив сеть.

Дополнительная настройка может включать:

- установку системной даты вручную (`date -s "$CURRENT_UTC_TIMESTAMP"`);
- настройку языка и раскладки клавиатуры.

### 2.1 Установка пакетов GnuPG без подключения к сети {#21-install-offline-packages-for-gnupg}

Загрузившись в защищённую среду, пользователь проверяет контрольные суммы SHA256 пакетов APK, ранее проверенных с помощью GPG и скачанных на съёмный носитель:

```shell
root@host:~$ mkdir work && cd work
root@host:~/work$ mount -t exfat "${SD_PARTITION_DEV}" /mnt
root@host:~/work$ cp /mnt/airgap-bundle.* .
root@host:~/work$ umount /mnt
```

Следующая команда жёстко связывает (`&&`) криптографическую проверку созданного ранее архива с его последующей распаковкой. Если контрольная сумма неверна, архив не будет распакован, и следующая за этим команда `apk` должна завершиться ошибкой.

```shell
# Require sha256sum to pass before extracting and installing with `apk`
root@host:~/work$ sha256sum -c airgap-bundle.tar.gz.sha256 \
                  && tar -xzvf airgap-bundle-tar-gz \
                  && apk --allow-untrusted --force-non-repository add *.apk
```

**Не забудьте!** Если вы заранее скачали копию [gpg.conf](https://github.com/drduh/YubiKey-Guide/blob/master/config/gpg.conf), обязательно скопируйте её в `$GNUPGHOME` перед продолжением.

**Замечания для CI/CD.** Для команд DevOps на этом заканчиваются основные требования к подготовке образа Alpine Linux с копией пакетов для автономного управления ключами GPG. Ради прозрачности обязательно включите все соответствующие шаги и артефакты в сведения о происхождении программного обеспечения (software provenance) и в подпись образа перед выпуском.

### 2.2 Проверка среды {#22-verify-the-environment}

Если пакеты установлены успешно, приступите к проверке среды для работы с GPG:

**Примечание.** Если у вас есть YubiKey, подключите его сейчас.

```shell
# Verify GPG installation
root@host:~$ gpg --version

# Verify smartcard connection
root@host:~$ gpg --card-status

# Import corresponding public key to view all details
root@host:~$ gpg --import yubikey.pub
root@host:~$ gpg --list-sigs "$YUBIKEY_FINGERPRINT"
root@host:~$ gpg --list-secret-keys "$YUBIKEY_FINGERPRINT"
```

**Примечание.** Если при переключении между каталогами `$GNUPGHOME` (что часто бывает при интенсивной работе с ключами, например при переносе связок ключей) YubiKey перестаёт определяться, попробуйте перезапустить `gpg-agent`:

```shell
root@host:~$ pkill gpg-agent
root@host:~$ gpg --card-status
```

**Готово!** Теперь вы можете начать [работу с GPG](https://github.com/drduh/YubiKey-Guide?tab=readme-ov-file#identity) и смарт-картами в новой изолированной от сети среде!

## Этап 3. Ликвидация {#stage-3-takedown}

После завершения работы с ключами защищённую среду следует либо а) сразу уничтожить, либо б) надёжно убрать на хранение, чтобы закрыть окно для неизвестных угроз неиспользуемой системе (например, физических, технологических, теоретических, неизвестных).
